# Changelog

One line per merged PR, newest first: what changed for agents or the owner, and why. Decisions behind a change are in `decisions/`.

- **#44** Matt Pocock's `grilling` added unchanged to `vendor/`, at the owner's request: stress-test a plan, decision or idea through rounds of questions (see `decisions/2026-10-19-vendor-grilling.md`).
- **#43** New `writing/animated-explainer` skill: narrated, animated explainer videos (Manim, free local Kokoro voice), one per chapter, from slides, a PDF or notes. It works from a source-of-truth summary and a humanised script, and nothing renders final until a layout check, a beat-by-beat review and an accuracy check pass. On the thread's first video, the checker found 18 defects that thumbnail QA had missed, including the 3 the owner spotted, and audio moved from -20 to -12.6 LUFS (see `decisions/2026-10-19-animated-explainer-skill.md`).
- **#41** Inside T3 Code, reviews run through `delegate_task` in a worktree instead of the CLI, so the reviewer shows as a child thread (#38). Its write access is checked rather than blocked: commit first, tell the child not to write, then confirm HEAD, `git status`, the remote's branches and the child's worktree are unchanged, then remove the child's worktree and branch, which T3 leaves behind. Trials: Codex and Claude reviewers ran unattended and wrote nothing; a canary that wrote on purpose was caught. Sol-implemented now includes code written by a delegated Sol child. A new scenario passed 0 of 6 runs with the old profile text and 8 of 9 with the new (see `decisions/2026-10-18-t3-reviews-in-worktree.md`).
- **#40** Wording follow-up to #39, no behaviour change. The `dev-skills/README.md` rows for `long-running-commands` and `html-communicate` now mention the harness wake-up and inline delivery; `html-communicate`'s inline rule overrides only the Build section's styling, never the content rules; `profile.md` states the T3 review exception once, under Reviewer routing.
- **#39** Inside T3 Code, kook follows T3 where its tools cover the same job (#36, items 2 and 4). `long-running-commands` and `full-cycle`: a harness tool that wakes you (T3's PR watch, an async task's wake-up) counts as waiting, so ending the turn after starting it is fine; without one, keep polling. `html-communicate`: show the page inline when the harness can, checked with its preview, and serve a link only otherwise. Reviews stay on the CLI route, because T3's `delegate_task` reviewers aren't read-only (revisit in #38). A new inline-page scenario passed 1 of 3 runs before and 2 of 3 after; the two waiting scenarios passed 3 of 3 before and after (see `decisions/2026-10-17-follow-t3-where-it-overlaps.md`).
- **#37** `scripts/t3-thread.sh` reads T3 Code 0.1.0's `statev2.sqlite` first, falling back to `state.sqlite`, and pre-V2 transcripts that still sit in the legacy tables. V2 copies the old database once and stops writing to it, so the script would have returned "no thread" for every new thread (#36, item 1).
- **#35** `requesting-code-review`: the implementer judges each review finding before acting (fix by default; doesn't hold, with evidence; decline a preference; report), treats severity as a claim, questions an earlier review fix before stacking code on it, and lists every finding's verdict in the PR; the review budget goes from 2 fix rounds to 3. An audit of 23 threads found agents fixing findings they doubted, piling fixes on fixes, and dropping declines. On a new scenario, Codex passed 1 of 3 runs before and 3 of 3 after; Claude Opus passed 3 of 3 both times (see `decisions/2026-10-16-judge-review-findings.md`).
- **#30** Matt Pocock's `handoff` and `teach` added unchanged to `vendor/`, at the owner's request. Both are manual only: run `/handoff` or `/teach` (see `decisions/2026-10-15-vendor-handoff-teach.md`).
- **#27** `html-communicate`: describes the reader and what the page must do, with the findings layout as a default to adapt; drops the 25-word cap, the fixed section order, the stat-tile quota and exact sizes. Borrows show-me's "smallest view" rule so pages stay short without a word cap. Delivery and honesty checks stay exact. On a new-teammate explainer, the old rules put "What I need from you" on the teammate's page in 6 of 7 runs; the new skill passes 3 of 3, and the existing scenarios still pass (see `decisions/2026-10-14-html-communicate-reader-not-template.md`).
- **#28** New `pr-body` skill owns every rule about the PR body and the final report; `full-cycle`, `requesting-code-review` and the `github` PR guide route to it, so `full-cycle` stays the orchestrator. It adds Merge danger (can a revert undo it, what could break, by name) and before/after Evidence, borrowed from Matt Pocock's `pr` skill. On a scenario built from Bokli #70, Claude Sonnet passed 0 of 3 runs before and 6 of 6 after (see `decisions/2026-10-14-pr-body-skill.md`).
