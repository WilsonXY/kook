# Claude Code uses Haiku subagents for fan-out work

**Context.** In the 14 days to 2026-10-10, 2 of 66 Claude Code sessions on this machine spawned any subagent, and none chose a model, including sessions with 200 to 490 tool calls. Claude Code's Agent tool description tells the model not to spawn unless the user asks, and that a "thorough" or many-part task is no such request. The owner wants Claude to fan out to cheap subagents the way Theo's PR-audit prompt does, on Haiku 5.5 (owner, thread 6bf1af55). Codex should not get this rule.

**Decision.** `profile-claude.md` holds Claude-Code-only setup. `sync-skills.sh` links it as `~/.claude/rules/kook-profile.md`, which Claude Code loads at session start and Codex never reads. Its first rule: a standing request to spawn subagents for five or more independent items that each need their own reading, on `model: "haiku"` with `effort: "high"`, while the main agent keeps the plan, the cross-item judgement, the edits, and checks claims before acting on them.

**Evidence.** `claude -p --model opus` in a throwaway config dir, with and without the rule, read-only:
- Audit the last 12 merged PRs, rule at max effort (verification stated? CHANGELOG line matches diff?): 0 spawns in 2 runs without; 6 Haiku/max spawns (2 PRs each) in 2 of 2 runs with. Cost $0.47 and $0.59 without, $1.10 and $0.99 with. Wall time 90 and 100 s without, 480 and 476 s with: each Haiku subagent took 200 to 413 s, and 95 to 97% of its output tokens were thinking (421k to 460k of 444k to 475k per run). The main agent's peak context did not shrink (45k to 56k with, 47k to 51k without), and its Opus cost did not drop, so the Haiku spend was added on top rather than replacing Opus spend. One run with the rule caught and corrected a wrong subagent finding. Without the rule, the trial's `gh`-only allowlist blocked 3 and 17 shell loops, so those runs grepped CHANGELOG hunks instead of reading whole diffs; the baseline was partly held back by the trial setup.
- The same audit with the rule at high and at medium effort, 2 runs each (wall time; total cost; Haiku output tokens; time per subagent). Max: 480/476 s; $1.10/$0.99; 444k/475k; 200 to 413 s. High: 126/135 s; $0.43/$0.83; 37k/46k; 13 to 64 s. Medium: 110/84 s; $0.47/$0.57; 22k/19k; 13 to 41 s. All three settings found the same headline problems (#11 and #8 without their own CHANGELOG line, overclaiming lines in #17 or #20). Answers were compared by reading, not graded. In one high run the main agent answered before the last subagent finished and filled those rows from its own reading, saying so. A first batch at high and medium hit the owner's 5-hour usage limit mid-run and was discarded; the two max runs had used about 920k Haiku output tokens just before.
- Two-sentence question about one script: 0 spawns with or without, as intended.
- A first wording ("standing request", no size threshold, no "counts as the user asking") spawned nothing on a 13-skill audit, the same as no rule.

**Rejected.**
- A "Claude only" section in `profile.md`: Codex loads that file too and would read it.
- An `@import` line in `profile.md`: Codex would see a stray line, and Claude Code already loads `~/.claude/rules/` on its own.
- Max effort, the owner's first ask: about 4 times slower than high and 10 times the Haiku tokens, with no visible gain on the audit, and it eats the subscription's usage limit.
- Medium effort: fastest here, but the audit was easy. High keeps some thinking for harder subagent work.
- Letting the model pick a subagent model per piece: the owner asked for Haiku on every subagent. Reopen if a session shows Haiku failing a piece that needed a stronger model.
